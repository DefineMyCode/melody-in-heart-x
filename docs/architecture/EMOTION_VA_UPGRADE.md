# 情绪 V/A 语义改造方案（待拍板）

> 日期：2026-10-24 · 状态：**方案稿，未动代码**
> 依据：Redmi 23113RKC6C 上 1095 首曲库的**零人工标注**诊断（`tools/emotion_diag.py`）
> 前置：诊断脚本已入库（`d927f82`）；`userTagsEdited` 采集改造已先行落地（DB v12）

---

## 0. 一句话

把 **arousal** 从"VA 头回归出的曲风代理"换成**直接算的响度包络**（物理定义，定义即准）；
把 **valence** 从"未经标定的回归输出"换成**经零点/斜率标定的输出**。

> **模拟结论（2026-10-24，见 §10）**：
> **A 是必需的**——它是唯一能救「燃」「静谧」的一步（valence 标定后「燃」只剩
> 2.0% 的歌，换成真实响度后回到 24.6%）。
> **B 是有益的**——V 均值 0.264→0.017，词条极差 6.03×→2.71×，半曲一致性 48.5%→62.3%。
> **C（锚点重标定）不必做**——A 的映射区间选对之后，原锚点在新坐标下依然语义正确，
> 而 k-means 重匹配在 9 簇/9 组的分配上噪声大，**实测保持原锚点比重标定更好**
> （详见 §10.3）。C 降级为「重扫后的可选复查项」——锚点只影响投票、不影响
> 存储的曲线，所以事后重算是零成本的。
>
> 另有一条硬约束（若将来做 C）：**锚点重标定的位移比较必须在标定前坐标系里做**，
> 否则 B 的全局平移会被误算成语义漂移，C 会退化成 no-op（§10.4）。

**参数定稿**（模拟得出，见 §10.5）：
A = `-30..-5 dBFS → [-1,1]` · B = `(v-0.25)/0.85` · C = **不做，锚点保持不变**

| 指标 | 实测 | 判读 |
|---|---|---|
| valence 逐窗分布 | mean **+0.263**，std 0.407，范围 [-1.000, +0.997] | 分布健康，但**系统性正偏** |
| arousal 逐窗分布 | mean +0.096，std 0.423，范围 [-1.000, +1.000] | 同上 |
| V-A 相关 | pearson **+0.294** / spearman +0.315 | **未塌缩**，两轴在做不同的事 |
| 未定率 | **11.9%**（130/1095） | 健康，远好于预期 |
| 逐窗弃权率 | 5.9% | 投票信息充足 |
| Bootstrap top1 稳定率 | 均值 **81.2%**，中位 87%（<30% 的歌 0 首） | 词条是稳健属性，非掷骰子 |
| 半曲一致性 | **48.8%** vs 随机基线 11.1% | 4.4× 随机，有稳定信号 |
| 窗内方差占比 | valence 69.9% / arousal 63.2% | 曲线有真实起伏，"高潮"定位不是摆设 |
| 艺人级 ICC | valence **+0.661** / arousal **+0.671** | **2/3 方差由"谁唱的"解释**（音色主导） |
| 锚点偏移 | 窒息 0.84 / 燃 0.70 / 躁 0.50 / emo 0.40 / 静谧 0.38<br>（正面四组仅 0.06~0.19） | **负面组与高能量段锚点严重脱节** |

**结论**：模型输出**是健康的**（无塌缩、未定率低、稳定性高）——所以**不重训**。
问题出在**语义**与**标定**：arousal 测的是曲风不是能量，valence 有正偏，锚点按旧假设定的没跟上。

> 明显不该在的位置），不作为"必须贴合"的指标。

## 3. 方案 A：arousal → 响度包络

### 3.1 语义定义

```
arousal := 该时刻的响度（dBFS）经固定映射后的值 ∈ [-1, 1]
```

- **绝对**能量：整曲都很响 → 整曲投"燃"；最响那 20 秒 → "高潮"落点
- 不再是"这首歌像不像电子乐"

### 3.2 实现位置（零额外解码成本）

`EmotionAnalyzer` 解码链已握有全部 PCM，`resampleTo16k()` 之后就是 16k mono `FloatArray`：

```
解码 → ShortAccum → resampleTo16k → FloatArray(16k)
                                     ├─→ 切 5s 窗 → RMS → dB → arousal   ← 新增，纯本地算
                                     └─→ 切 16384 帧 → YAMNet → VA 头 → valence
```

不碰 YAMNet、不碰模型权重、不增加解码开销。

### 3.3 映射函数

```
rms      = sqrt(mean(x²))                    // 窗内 16k 样本
db       = 20 * log10(rms + 1e-6)             // ≈ -120..0 dB
arousal  = clamp((db - DB_FLOOR) / (DB_CEIL - DB_FLOOR) * 2 - 1, -1, 1)
```

`DB_FLOOR` / `DB_CEIL` 三个候选：

| 方案 | 取值 | 优点 | 代价 |
|---|---|---|---|
| **A1 物理固定** | −60 dB / 0 dB | 绝对、可解释、不随曲库变 | 不同母带响度的歌被拉开（可能正是想要的） |
| A2 曲库自适应 | 库内 dB 的 p5/p95 | 区分度最大 | **随曲库变化 → 同一首歌在两台设备上词条可能不同** |
| A3 混合 | 固定 + 曲级归一 | 兼顾 | 复杂度高，收益不明 |

**推荐 A1。** A2 的不可复现性是硬伤（删一首歌可能让别的歌词条变化，用户会认为功能有 bug）。
"燃/静谧"本来就是**绝对能量**概念，物理标定与语义一致。

### 3.4 与 VA 头的关系

arousal **不再取自 VA 头**（头仍输出 arousal，但被 RMS 覆盖）。
valence 继续取自 VA 头——它是 YAMNet→valence 的学习结果，有信息（V 轴贡献 51.6%）。

**必须验证**：valence 单独用是否还够好？→ §3.5 已给出一个必须一并修的缺陷。

### 3.5 一个已存在的锚点设计缺陷（必须一并修）

> **"元气"(0.6, 0.4) 与 "治愈"(0.6, −0.1) 的 `anchorV` 完全相同。**

双轴投票时这两组只靠 arousal 区分。而这两个词条占了 **36% 的窗**（18.6% + 17.3%）。
一旦 arousal 换成绝对 RMS，它们的区分度完全押在 RMS 的分辨力上。

→ 这是 §5 锚点重标定必须覆盖的（两组必须拉开 `anchorV` 间距）。

## 4. 方案 B：valence 零点/斜率标定

### 4.1 三个候选

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **B1 固定标定**（推荐） | `v' = (v − B) / S`，B/S 由大规模曲库标定后写死 | 可复现、可解释、不依赖运行时状态 | 不同曲库的用户拿到同一组 B/S |
| B2 曲库自适应 | 运行时按本机曲库算 B/S | 每个用户的库都居中 | **删歌/加歌/分析进度不同 → 同一首歌词条会变** |
| B3 曲内相对 | `v − song_mean_v` | 完全消掉曲级偏置 | **语义变成"这首歌内部相对多正"**——全程都很悲的歌会趋近 0，反而判不出来。不可取 |

**推荐 B1。** B2 的不可复现性与 A2 同源，是同一个坑。

本次诊断给出的标定候选：曲库 valence 歌级 mean **+0.249**、std **0.242**
→ 候选 `B = 0.25, S = 0.85`（保留原尺度的一半 spread，避免过度放大噪声）
→ 需在离线模拟里对比几组 (B, S) 再定。

### 4.2 一个诚实的边界

valence 的正偏里，**有多少是模型偏、多少是曲库偏，无法分离**（没有真值）。
B1 假定"库均值应接近 0"——这在 ACG/OST 曲库上未必成立。

**缓解措施**：标定后**人工抽查 20 首**（听一下标定后的词条对不对），结论写进本文档。
这是唯一能在无真值条件下做的验证。

## 5. 方案 C：锚点重标定（必须跟随 A/B）

### 5.1 算法

1. 在**重标定后的逐窗输出**上做 9 簇 k-means
   （⚠️ 必须在**逐窗**上做，不是在歌级均值上——歌级均值方差被平均掉了，测的是别的东西）
2. 簇心与 9 个 `auto=true` 组锚点做 1-1 匹配（贪心最小距离，约束每个组恰好配一个簇）
3. 新锚点 = 簇心；迭代 2~3 轮（锚点变 → 分布变 → 再聚类）
4. 手动组（WITTY）不参与，无自动锚点

### 5.2 硬约束

- 锚点保持在 [-1, 1]² 内
- 组间最小间距 ≥ **0.25**（否则两个词条无法区分；这也会自动解决 §3.5 的"元气/治愈同锚点"）
- 锚点距离中心的最大值不宜超过 0.6（超出说明模型够不到，该组应当合并或调整语义）

### 5.3 风险（必须写进决策）

> **锚点重标定只让分布变好看，不让模型更准。**
> 没有真值就无法证明新的更好。它的正当性**完全来自**：A/B 改完后锚点必须跟着新分布走，否则更错。
> **不能单独做。**

**模拟补充的两条（§10）**：

1. **必须带位移约束**。本库不存在「高 V + 低 A」的组合（安静的歌都偏伤感），
   无约束匹配会把「治愈」配到**高能量**簇上——那不是不准，是**语义反了**。
   约束的做法：簇心离该组**原语义锚点**超过 `MAX_SHIFT`（定稿 0.40）就不参与匹配，
   该组**保持原锚点**。宁可让词条稀有，也不让它说反话。
2. **位移比较必须在标定前坐标系里做**。B 把 V 整体平移了约 0.29，
   若直接在标定后空间比较距离，这个平移会被误算成"语义漂移"，
   于是所有组都超限、锚点一个都不动，**C 退化成 no-op**。
   正确做法：把簇心用逆变换 `v0 = v*S + B` 还原回标定前空间再比距离。

旧数据保留在库里不被覆盖（除该曲重扫外）。

## 7. 明确不做的事

- **不重训 VA 头**——诊断显示输出健康（稳定率 81.2%、未定率 11.9%），且无真值无法验证"更准"
- **不换表征**（MERT/CLAP/Music4All）——`EMOTION_KNN_ANALYSIS.md` 已全部实测判负
- **不对齐外部 V/A 数据集**——曲库是 VOCALOID/动画 OST（552 艺人），非 Jamendo，无现成标注
- **不动词表规模**（10 组 39 词）
- **不把 ICC 0.66 当缺陷修**——它是表征性质；可作为推荐信号正向利用（见 §8）

## 8. 一个可以顺带做的正向利用

ICC 0.66 意味着"同一艺人的歌被模型给相近分数"。
在**推荐**场景这是有效信号（用户喜欢澤野弘之的燃曲 → 推同艺人的燃曲命中率高）。

具体：探索播放补队列时，把"同艺人 + 标签一致"作为加权项。

**前提是诚实改名**——UI 上别再把这个信号叫"情绪"，可以叫"同风格/同制作人"。
这样 ICC 从"测量缺陷"变成"可利用的亲和度信号"。

## 10. 离线模拟结果（2026-10-24，参数定稿依据）

工具：`tools/emotion_sim.py`（复用 `emotion_diag.py` 的投票逻辑，避免两处失真）。

```powershell
# 音频样本：从设备拉真实音频（adb exec-out cat → <songId>.<ext>）
python tools/emotion_sim.py --db melody.db --audio <音频目录>
# 全库 valence 侧分析（不需要音频，1094 首全参与）
python tools/emotion_sim.py --db melody.db --audio <目录> --full-library --only-no-a
```

**样本口径**：真实音频样本 69 首（覆盖 16+ 艺人，含 FLAC 96k/24bit、MP3、M4A、WAV），
拉取后用 ffmpeg 解码成 16k mono，按 5s 窗/2.5s hop 算 RMS→dB（窗口起点与
`EmotionAnalyzer` 的滑窗逐窗对齐）。valence 侧分析跑全库 1094 首。

### 10.1 真实响度分布

**（a）ffmpeg 路径**（初版模拟用的口径）：```
min -87.8 dBFS | p5 -28.1 | median -11.8 | p95 -5.2 | max -3.4
```

**（b）app 精确路径**（`EmotionAnalyzer` 实际走的路径，真机复核后重标）：```
p1  -43.34 | p5  -31.19 | p25 -19.58 | p50 -14.76 | p75 -11.40 | p95  -8.20 | p99  -7.32
min -89.80 | mean -16.76 | max -6.41
```

> ⚠️ **两条路径差约 3 dB，参数必须按 (b) 定。**
> 原因：`EmotionAnalyzer.resampleTo16k` 是**线性插值重采样**（无抗混叠滤波），
> 高频折叠使 RMS 略低于 ffmpeg 的带滤波重采样。
> **这不是 bug，也不能改**——同一份 PCM 还要喂给 YAMNet，改重采样会破坏
> 「与服务端训练逐位一致（maxDiff=6e-6）」的前提。正确做法是**按 app 实际口径标定映射区间**。
>
> 真机复核（2026-10-24）：取已重扫的歌，把真机曲线反解成 dB，与本地按 app 路径
> 复现的 dB **中位差 -0.00 dB** —— 真机测的就是它该测的，无系统性电平 bug。

**这个库比预想的响**（app 路径中位 -14.8 dBFS）。它直接否掉了 A1（-60..0dB）：
-60dB 的下限对 p5 只有 -31dB 的库来说太深，低能量段几乎不可达
（低能可达仅 **0.9%**），「静谧」「窒息」这类词条永远出不来。

| 方案 | 燃可达%（arousal≥+0.6） | 低能可达%（≤−0.5） | 判读 |
|---|---|---|---|
| A1 (-60..0) | 29.3 | **0.9** | ❌ 低端不可达 |
| A2 (-45..0) | **9.5** | 3.0 | ❌ 两端都不行 |
| A3 (-40..-5) | 29.3 | 4.9 | ❌ 低端仍不可达 |
| A6 (-40..0) | **3.8** | 6.0 | ❌ 高端不可达 |
| **A7 (-30..-5)** | **15.2** | **15.3** | ✅ **两端都可达** |
| A4 (自适应 p5..p95) | 35.2 | 12.1 | 分布最好但**不可复现**，不采用 |

### 10.3 三个关键结论

**① A（RMS）是必需的——它是唯一能救「燃」的一步**

top1 词条分布（用户实际看到的词）：

| | 治愈 | 静谧 | 神圣 | 放松 | 元气 | 躁 | emo | 窒息 | **燃** |
|---|---|---|---|---|---|---|---|---|---|
| 现状（全库 1094） | 519 | 164 | 451 | 576 | 457 | 138 | 210 | 73 | **154** |
| 只做 B（保留原锚点，全库 1094） | 282 | 227 | 182 | 111 | 99 | 67 | 60 | 44 | **22** |
| **A7+B（保留原锚点，样本 69）** | 2 | 4 | 7 | 3 | 30 | 4 | 1 | 1 | **17（24.6%）** |

valence 标定把 V 均值拉向 0 之后，「燃」这类**高能量**词条几乎归零（22 首 / 2.0%）——
因为模型的 arousal 够不到 +0.85（曲风代理的固有限制）。
换成**真实响度**后，「燃」回到 24.6%。**这是 A 不可替代的价值。**

**② B（valence 标定）是有益的——全库指标全面改善**

| 指标（全库 1094 首） | 现状 | B1 + 保留原锚点 |
|---|---|---|
| 歌级 V 均值 | +0.264 | **+0.114** |
| 词条覆盖极差 | 6.03× | **2.71×** |
| 冷门词条最少歌数 | 16 | **3** |
| 半曲一致性 | 48.5% | **62.3%** |
| Bootstrap 稳定率 | 81.1% | **85.4%** |

**③ C（锚点重标定）实测下来不必做——保留原锚点反而更好**

同批样本内横向比较（保留原锚点 = 「不C」）：

| 方案 | 词条极差 | 稳定率% | 半曲一致% |
|---|---|---|---|
| 现状 | 13.4 | 84.7 | 59.4 |
| **A7+B1+不C（保留原锚点）** | **7.17** | **90.5** | **65.2** |
| A7+B1+C（位移约束 0.25） | 9.14 | 88.4 | 59.4 |
| A7+B1+C（无位移约束） | 5.12 | 82.0 | 47.8 |

全库侧同样：不做 C 的词条极差 **2.71×** vs 做 C 的 6.33×。

**原因**：A 的映射区间选对之后（-30..-5dB），**原锚点在新坐标下依然语义正确**
（燃→-6.9dB / 治愈→-18.8dB / 静谧→-24.4dB，量级都对得上）；
而 C 的 k-means 要在 9 个簇和 9 个组之间做 1-1 分配，**高能量簇的划分噪声很大**
（69 首样本上「躁」的 arousal 在两次运行间从 +0.676 跳到 +0.375），
位移约束又让 C 大部分退化成 no-op，剩下的移动反而引入语义漂移。

**C 降级为「重扫后的可选复查项」**——锚点只影响投票、不影响存储的曲线，
所以重扫后想再算一次是零成本的（不必再扫一遍）。

<details>
<summary>若将来仍要做 C，两个必须避开的坑</summary>

1. **必须带位移约束**。本库不存在「高 V + 低 A」的组合（安静的歌都偏伤感），
   无约束匹配会把「治愈」配到 `(+0.561, +0.852)`——**高能量位置**，语义直接反了。
   约束做法：簇心离该组**原语义锚点**超过 `MAX_SHIFT`（0.40）就不参与匹配，
   该组**保持原锚点**。宁可让词条稀有，也不让它说反话。
2. **位移比较必须在标定前坐标系里做**。B 把 V 整体平移了约 0.29，
   若直接在标定后空间比距离，这个平移会被误算成"语义漂移"，
   于是所有组都超限、锚点一个都不动，**C 退化成 no-op**（实测偏移与「不C」完全相同）。
   正确做法：簇心先用逆变换 `v0 = v*S + B` 还原回标定前空间再比距离。

</details>

### 10.4 参数定稿

| 参数 | 取值 | 依据 |
|---|---|---|
| **A 映射区间** | `−30 .. −5 dBFS → [−1, 1]` | 固定物理区间（不随曲库变——自适应区间会导致同一首歌在两台设备上词条不同）。语义自洽：燃→−6.9dB / 治愈→−18.8dB / 静谧→−24.4dB。低能可达 10.0%、燃可达 36.5% |
| **B 标定** | `v' = (v − 0.25) / 0.85` | B=0.25 来自**全库**歌级 V 均值 +0.249（+0.264 是含 clamp 前的实测值）；S=0.85 保留原尺度八成、避免过度放大噪声 |
| **C 锚点** | **不做，保持现状** | §10.3③：实测保留原锚点全面更优；且锚点是语义定义而非数据统计量 |
| **A 的备选** | A4 自适应（库内 p5..p95） | 分布最均衡，但**不可复现**——同一首歌在两台设备上可能得到不同词条。**不采用** |

### 10.5 已拍板的产品决策

**「治愈」会变成稀有词条 —— 已接受**（2026-10-24）。
原因是语料属性而非 bug：本库的「高 V + 低 A」（愉悦但安静）组合本来就少，
现状下「治愈」有 519 首是因为 valence 正偏把大量歌推到了 +0.3~+0.6 附近——
**那不是「治愈」，是正偏的副产品**。改造后「治愈」只剩个位数曲目的占比，
其余词条重新分化——这正是这次改造的意图。

### 10.6 实现（2026-10-24 已落地）
