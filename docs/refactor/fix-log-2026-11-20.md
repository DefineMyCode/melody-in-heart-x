## 一、`:player` 模块

### M-1 `PlaybackController` 连接/释放生命周期竞态 ✅

**文件**：`player/.../PlaybackController.kt`

- 新增 `stateLock` 互斥锁、`released`（`@Volatile`）释放标志；`controller`、`lastSyncedQueueFingerprint`、`lastCurrentMediaItemIndex`、`pendingQueueMutation` 改为 `@Volatile`。
- `connect()`：release 后实例不可复用；重复 connect 时先 `removeListener` + `releaseFuture` 断开旧 controller。future 回调在锁内校验 `released` **与 future 身份**（`controllerFuture !== future`）后才挂载，旧 future 的失败/取消不再误报连接失败。
- `release()`：锁内先设 `released=true`，`releaseFuture` 取消 future，最后清空状态。
- `runWhenConnected()`：慢路径加锁保护 `pendingActions` 读改写（double-check）；动作与队列溢出回调都在锁外执行。
- `drainPendingActions()`：锁内取动作、锁外执行（由 future 回调在挂载后调用）。

### M-2 `playSingle()` 返回值不可靠 ✅

**文件**：同上。`return true` → `return runWhenConnected { ... }`，透传执行结果。控制器未连接时返回 `false`，上层不错误启动时长跟踪。

### M-3 `PlayDurationTracker` scope 未取消 + 字段可见性 ✅

**文件**：`player/.../PlayDurationTracker.kt`。`currentSongId`、`currentSongDurationMs` 改为 `@Volatile`；`release()` 取消 scope。

**复审修正**：`release()` 直接 `scope.cancel()` 会把刚提交的 `settlePlayback` 一并取消，退出时丢最后一段统计。改为先等 scope 内已提交的结算/计数协程完成，再取消（等待在 IO 线程，不阻塞调用方）。

**测试**：`PlayDurationTrackerTest` 的 `releaseFlushesFinalSettlementBeforeCancellingScope` 同时断言最后一次会话已落盘。

## 七、复审二次修复（2026-11-21）

复审针对 `c2f5fa2c` 逐条核对实现与测试，发现 4 处回归/残余风险并修复：

1. **OGG 歌词解析真机必失败**：`header_type 0x02` 是 BOS（流开始），不是包结束；真实 Comment 页 flags 为 `0x00`，解析会读到文件末尾并返回 null。测试夹具同样写错，把错误固化成绿测。按方案 B 摘除 `ogg/oga` 分支、辅助函数与测试，回到 FLAC/ID3v2，待真实样本后按 RFC 3533 段表重做。
2. **`PlayDurationTracker.release()` 丢最后一次结算**：`stopPlayback()` 提交 `settlePlayback` 后立即 `scope.cancel()` 会取消尚未执行的结算。改为等 scope 内已提交的结算/计数协程完成后再取消。
3. **空会话保存覆盖无限/探索播放标记**：UI/ViewModel 重建窗口的"空拍"会把磁盘上的 `IS_INFINITE_PLAY/IS_EXPLORE_PLAY` 写成 false，导致重建后或杀进程重启丢失会话。改为仅在无既有队列快照时清理。
4. **`EmotionAnalyzer` 进度回退**：锁内收集、出锁后批量上报仍发生在推理全部结束之后，进度条回到 0→100 一跳。恢复逐窗上报，并隔离回调异常。
5. **探索播放会话未落盘，重启后回到「无限随机播放」**（2026-11-21 二次反馈）：探索模式下清空队列 → 随心播放 → 杀进程 → 重启，播放页显示「无限随机播放」而非「探索播放中」。根因是 `playRandomQueue` 先 `setPlayQueue` 再置 `isExplorePlay`，而 `setPlayQueue` → `applyPlan` 内部会立即触发一次持久化保存，落盘的是 `explore=false`；随播后 5 秒内杀进程，autosaver 来不及写回 true。修复：先更新会话标记，再以 `exitInfinitePlay=false` 替换队列（不把刚置位的标记清掉）；`startInfinitePlay` / `stopInfinitePlay` / `stopExplorePlay` 也改为状态变更后立即排队保存。

同时收尾：`PlaybackController` 删除无效的 `futureListener` 字段、future 回调增加身份校验（旧 future 不再挂载/误报失败）、`runWhenConnected` 与 pending 动作改锁外执行；`getOutputFormat` 注释明确"只消费事件、不改解析参数"。

**未改动（经核实）**：M-2 `playSingle` 在控制器未连接时返回 false 的副作用会被 `ControllerPlaybackStateSynchronizer` 的 `playbackStart` 补偿（`trackedSongId` 与计时在首次快照同步时补上），故保留现状。
